Task 3 · Reading the instructions

Five sections, five jobs.

The instructions you just pasted aren't one block of prose — they're five parts, each doing distinct work. Here's what each one does and why it's there.

01

What each section does

01
Scope What the agent answers

Two question types — player and team history, and the rules of baseball. Anything outside that is out of scope by definition.

02
Tool usage How it gets the answer

The agent must use the profiles_and_rules tool. Every factual claim has to trace back to a retrieved chunk.

{@TOOL: profiles_and_rules}  ·  CX Agent Studio syntax — resolves at runtime to tell the model which tool to invoke
03
Tone The audience pivot

Fan-voiced, warm, enthusiastic. Different register from the scouting brief agent's analyst voice — same data, different audience.

04
Out-of-scope handling Most important

Tells the agent exactly what to do when fans ask about current state: defer politely, redirect to authoritative sources, offer to help with what's in scope.

05
Language matching Mirror the user

Explicit instruction to mirror the user's language. The model already detects 40+ languages organically — this paragraph makes the behavior reliable, not just probable.

02

Why the tone bullet matters more than it looks

Same documents, same retrieval. Different register on top. That register is what turns shared infrastructure into audience-specific product.

Same data · Two voices

The retrieval is identical. The persona is not.

Veteran outfielder. Three-time All-Star. Career OPS+ of 124. Key rules consideration: outfield interference under Rule 6.01(d)…

Task 3 · Fan Agent

Voice is not decoration. It's the layer that makes one agent useful for scouts and the other useful for fans — using the exact same documents underneath.
